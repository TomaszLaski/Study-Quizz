A1  Debounced async search  typeahead / autocomplete / live search
PROBLEM
User wpisuje tekst, ty pokazujesz pasujące wyniki z API. Nie chcesz odpytywać API przy każdym znaku.
SŁOWA-KLUCZE W ZADANIU
as the user types  ·  search  ·  find matching  ·  autocomplete  ·  dropdown of results
KIEDY STOSOWAĆ
Wyszukiwarka, picker miasta/użytkownika, filtr który odpytuje serwer. Zawsze gdy input tekstowy
steruje zapytaniem sieciowym.

Część IV — Wzorce architektoniczne: nazwij to, co już robisz
Te wzorce już SIEDZĄ w twoim kodzie z A1–A10. Senior różni się tym, że umie je nazwać i uzasadnić na
głos.
Container / presentational
Każdy twój orchestrator + głupie komponenty to dokładnie to. Logika i stan w kontenerze, render w
komponentach bez własnego stanu. Uzasadnienie: testowalność renderu bez mocków sieci, reużycie
prezentacji z inną logiką.
Lifting state up
selectedId w rodzicu (A4), stan wizarda w orchestratorze (A6), wybory kaskady w kontenerze (A8).
Zasada: stan mieszka w najniższym wspólnym przodku wszystkich, którzy go czytają lub piszą.
Custom hook extraction
Każde useSearch, useAutosave, usePaginatedFetch. Komponent mówi CO, hook wie JAK. Sygnał do
ekstrakcji: useEffect z logiką dłuższą niż kilka linii albo duet stan+efekt używany w dwóch miejscach.
Compound components
Tabs, Accordion, Menu: rodzic trzyma stan aktywności, dzieci czytają go przez context zamiast łańcucha
propsów. Sięgnij, gdy API komponentu w propsach zaczyna wyglądać jak konfiguracja XML.
Reducer jako maszyna stanów
Twoje B2 potraktowane formalnie: stany + zdarzenia + przejścia zamiast luźnych setterów. Nielegalne
przejście nie istnieje w typach. Sygnał: trzy powiązane useState aktualizowane zawsze razem.
Kolejność nauki: A1–A5 metodą aktywnego przypominania → A6 wizard → A7 data table → B5 cache/dedup →
A8 → reszta wg potrzeb. Wzorce wchodzą do głowy przez rozpoznawanie w zadaniach, nie przez czytanie. Ten
PDF to mapa — trening to ćwiczenia. Wracaj tu z pytaniem, nie biernie.
